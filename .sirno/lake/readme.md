The README serves people evaluating Sirno and people starting their first managed project.
It explains the relationship between named design entries, repository evidence, and review,
then gives the reader a runnable path to an accepted design change.

The onboarding example covers project setup, entry creation, witness inspection,
an actual dependency-review obligation, and acceptance into Anchor.
Expected outputs explain pending review and identify successful completion.
Editing guidance distinguishes canonical source from projections and states generated-region ownership.
Agent setup explains the connection and skill entry point needed to perform the same project work.

Capability claims describe implemented behavior.
Future work remains identifiable as future work.
Command inventories come from the CLI's generated help;
the README selects commands for its walkthrough instead of maintaining another reference list.
Detailed behavioral contracts remain in their owning lake entries.
The `introduction` and `methodology` entries provide deeper reader routes.

The README's witness blocks identify its purpose, runnable workflow,
editing guidance, agent setup, and capability claims.
These regions demonstrate the reader contract stated here.
